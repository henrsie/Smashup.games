# Node–Python headless bridge

The Node process owns the authoritative game state. Python receives observations and ordered legal actions, chooses an `actionIndex`, and sends only that index back to Node for validation and execution.

Start the local environment API from `backend/`:

```bash
npm run env-server
```

In another terminal, run the dependency-free Python smoke test from the repository root:

```bash
python3 python/smoke_test.py --seed 380
```

Install PyTorch before using the trainable action encoder:

```bash
python3 -m pip install -r python/requirements.txt
```

`NodeSmashUpEnv` in `node_env.py` exposes:

- `reset(...)`: creates or resets an environment and returns its first observation and `legalActions`.
- `step(action_index)`: returns the next observation, legal actions, reward, termination flags, and transition metadata.
- `result()`: returns the episode summary.
- `save_trajectory()`: saves a completed recorded episode under
  `training-data/trajectories/`.
- `close()`: deletes the environment from Node memory.

Create the environment with trajectory recording enabled, finish or truncate the
episode, and then save it:

```python
state = environment.reset(seed=380, record_trajectory=True)

# Call environment.step(...) until terminated or truncated.

saved = environment.save_trajectory()
print(saved["path"])
```

The corresponding HTTP endpoint is:

```text
POST /environments/:environmentId/trajectory
```

It returns `409` while the episode is active or if trajectory recording was
disabled. Saving the same completed episode again returns the original file
instead of creating a duplicate. Filenames are generated by Node; clients cannot
supply filesystem paths. Generated trajectory JSON files are ignored by Git.

Stable action-type, choice-type, card-zone, card, faction, and base integer IDs are stored in `../shared/gameEntityIds.json` so both Node and Python load the same committed mapping. ID `0` is reserved for unknown or non-applicable entities. Add new entities with new IDs; do not renumber existing entries. Observations report `entityIdSchemaVersion`. Legal actions include `actionTypeId`, `choiceTypeId`, entity IDs, and structured `choiceFeatures` for seats, zones, board positions, selection counts, and numeric choices.

`create_entity_embeddings()` in `action_embeddings.py` creates separate trainable PyTorch tables for action types, choice types, card zones, cards, bases, and factions. Calling the returned module with the ordered `legalActions` list produces one vector per legal action. Source-card, target-card, and pooled selected-card embeddings share the same card table, so the same card learns one identity representation across action roles. Positional features distinguish identical card copies and targets, while explicit choice types distinguish outcomes such as accept, skip, cancel, and finish selection.

```python
from action_embeddings import create_entity_embeddings

action_embeddings = create_entity_embeddings()
action_vectors = action_embeddings(state["legalActions"])

# [number_of_legal_actions, action_embeddings.action_embedding_size]
print(action_vectors.shape)
```

`create_observation_encoder()` converts each variable-size observation into one
fixed-size trainable state vector. Pass the legal-action embedding module into the
observation encoder so cards, bases, and factions use the same learned lookup
tables in both contexts:

```python
from action_embeddings import create_entity_embeddings
from observation_encoder import create_observation_encoder

entity_embeddings = create_entity_embeddings()
observation_encoder = create_observation_encoder(
    entity_embeddings=entity_embeddings,
    state_size=256,
)

state_vector = observation_encoder(state["observation"])
action_vectors = entity_embeddings(state["legalActions"])

print(state_vector.shape)   # [256]
print(action_vectors.shape) # [number_of_legal_actions, 151]
```

The observation encoder represents the observer separately, pools the opponents,
pools each base and its played or attached cards, and includes turn, draft, pending
decision, and public count information. Entity IDs are embedded; bounded numeric
features such as victory points, power, and deck counts are scaled separately. A
list of observations can also be passed to produce `[batch_size, state_size]`.

The server also places up to 32 chronological machine-readable records in each
observation's `recentEvents`. Event types have stable IDs in the shared registry,
and cards, bases, factions, actors, targets, amounts, and resolution metadata use
structured fields instead of battle-log prose. The observation encoder passes
these events through shared entity embeddings and an order-sensitive GRU before
adding the resulting history vector to the state representation. Private ability
choice entities are retained for the choosing player and replaced with unknown
IDs for other observers. Natural-language `recentBattleLog` text and hidden
opponent hands are intentionally not encoded.

## Loading training trajectories

`TrajectoryDataset` loads one JSON file, a list of files or directories, or the
default `training-data/trajectories/` directory. It validates schema versions,
stable IDs, observations, rewards, terminal flags, legal-action encodings, and
the relationship between `chosenActionIndex` and `chosenAction`. Files are sorted
before their decision entries are flattened, so dataset indexes are reproducible.

```python
from trajectory_dataset import TrajectoryDataset

dataset = TrajectoryDataset()
transition = dataset[0]

observation = transition["observation"]
legal_actions = transition["legalActions"]
target_action_index = transition["chosenActionIndex"]
reward = transition["reward"]
```

Each item deliberately retains the raw variable-length observation and legal
action list. Tensor encoding, action padding, and action masks belong in a custom
batch collator, which can apply the shared observation and action encoders after
samples are selected. By default both native and migrated event histories are
accepted. Restrict training to native structured histories with
`event_history_sources=["native-v1"]`.

## Migrating older trajectories

New trajectories use trajectory and observation schema v5, entity schema v4, and
structured-event schema v1. Migrate a previously exported v4 JSON file into a new
file with:

```bash
.venv/bin/python python/trajectory_migration.py \
  old-trajectory.json migrated-trajectory.v5.json
```

The command refuses to replace an existing destination unless `--force` is
provided. The migration preserves observations, actions, rewards, and metadata,
updates their schema versions, and reconstructs ordered decision events from each
chosen action. Since old battle-log prose cannot reliably reconstruct every
automatic result, migrated files are marked with
`eventHistorySource: "decision-backfill-v1"` and
`automaticOutcomeEventsReconstructed: false`. Newly recorded trajectories are
marked `eventHistorySource: "native-v1"`, allowing a training pipeline to filter
or weight the two sources differently.

The local server binds to `127.0.0.1:3001` by default. Override it with `HEADLESS_ENV_HOST` and `HEADLESS_ENV_PORT`. Do not expose this development API publicly without authentication, rate limiting, and environment lifecycle limits.
